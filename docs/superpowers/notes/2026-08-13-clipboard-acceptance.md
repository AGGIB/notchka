# Приёмка плана «Хранилище и буфер обмена»

Ветка `feat/clipboard`, 31 коммит. Тестов 174, релизная сборка без
предупреждений компилятора.

## Что построено

История буфера обмена целиком: SQLite через GRDB 7.11.1 с миграциями и
полнотекстовым индексом, контент-адресуемое хранилище блобов с
дедупликацией по SHA-256, три слоя защиты от паролей, опрос пастборда с
паузой при неактивности, вытеснение по трём независимым пределам, вставка
в активное приложение через синтетический ⌘V, клавиатурное управление
вкладками, онбординг разрешения Accessibility.

Сверх плана, по ходу дела и по просьбам владельца: колонка вкладок слева,
укрупнённая обложка, бегущая строка у длинных названий, кнопки перемотки
трека, пересинхронизация панели после перехвата сессии уведомлением,
подпись постоянным сертификатом.

## Проверено человеком на живой машине

- Клавиатура: ⌥Space открывает панель, Esc закрывает.
- Лента буфера, источники подписаны именами приложений.
- Перекрытие содержимого чёлкой — было, исправлено, проверено.
- Разрешение Accessibility слетало при каждой пересборке — причина
  найдена (ad-hoc подпись), исправлена сменой сертификата.
- Панель зависала на звуке уведомления WhatsApp — причина найдена
  (система не шлёт события о возврате к прежнему источнику), исправлена
  разовой пересинхронизацией.

## Осталось на потом

- **Приватность отдельной придирчивой проверкой не пройдена.** План
  требовал: скопировать из 1Password и Связки ключей, убедиться, что в
  историю не попало, и открыть базу глазами. Логика проверена ревью и
  тестами, живьём — нет. Стоит сделать перед тем, как полагаться на
  историю всерьёз.
- **Расход не замерен**: CPU в покое и при активном копировании, объём
  базы после сотни элементов.
- Карточка ленты кликается через onTapGesture, а не Button — трейт для
  VoiceOver есть, настоящей клавиатурной активации нет.
- Опрос разрешения не ловит его отзыв посреди открытой вкладки; при
  отзыве обратной связи не будет никакой, кроме строки в журнале.
- Восстановленный из истории файл остаётся во временном каталоге до
  следующей выдачи — вне хранилища приложения и вне политики вытеснения.
- Обновление дубликата переписывает всю строку ради одной колонки.
- Сертификат разработчика действует до 28 февраля 2027; после обновления
  разрешение Accessibility придётся выдать заново, один раз.

## Чем этот план отличался

Ревью нашли 1 Critical, 14 Important и десяток Minor. Больше половины
находок — расхождение комментария с тем, что код делает на самом деле; за
это правило пришлось биться в каждой второй задаче, включая мои
собственные правки.

Финальное ревью всей ветки нашло то, чего не увидели одиннадцать
отдельных: вся тяжёлая работа буфера шла на главном потоке, хотя семь
комментариев и целый коммит утверждали обратное. `Task(priority:)`,
созданный внутри метода @MainActor-класса, наследует его изоляцию, а
`nonisolated` без `async` с актора не уводит — ошибка сложения, где каждая
задача по отдельности была права.

Три дефекта нашёл владелец за минуты работы с приложением. Ни один из них
не был виден по коду: перекрытие чёлкой требовало знать настоящую высоту
выреза, зависание панели — живого уведомления, слетающее разрешение —
понимания того, как macOS привязывает доступ к подписи.

# Notchka — интерактивная чёлка для macOS

Дата: 2026-08-10
Статус: дизайн утверждён, готов к планированию реализации

## 1. Что это

Приложение-агент для MacBook с чёлкой, которое превращает вырез в интерактивную панель
с четырьмя функциями: управление музыкой из любого источника, история буфера обмена,
быстрые заметки и закреплённые сниппеты для часто вставляемых значений.

Личный инструмент для ежедневного использования на собственной машине. Не публикуется,
не распространяется, не проходит нотаризацию. Это снимает ограничения на приватные API,
сэндбокс и App Store review, и определяет техническую стратегию (см. §4).

Приложение не делает ни одного сетевого запроса. Все данные остаются на диске машины.

### Целевая среда

- macOS 26.3 (Tahoe), Apple Silicon
- Swift 6.3, Xcode 26.6
- Встроенный дисплей MacBook с аппаратной чёлкой

## 2. Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Назначение | Личный daily-driver | Приватные API разрешены, локальная подпись, без сэндбокса |
| Взаимодействие | Три состояния: `closed → peek → expanded` | Логика Dynamic Island: наведение даёт информацию, клик даёт управление |
| Источник музыки | MediaRemote через perl-адаптер + AppleScript | Единственный способ читать браузеры без установки расширений |
| Визуальный язык | «Обсидиан» — чистый чёрный, акцент из обложки | Панель бесшовно продолжает физическую чёлку и выглядит как железо |
| Физика движения | Упругая пружина | `response 0.34 / dampingFraction 0.68` — ощущение живого материала |
| Раскладка буфера | Горизонтальная лента | Панель остаётся низкой, картинки видно как картинки |
| Вставка | Клик вставляет, `⌥`клик копирует | Требует разрешения Accessibility |

Рабочее имя: **Notchka**, bundle id `kz.mobilefirst.notchka`. Переименование дёшево до
первого запуска (bundle id входит в путь к хранилищу).

## 3. Архитектура

Xcode-проект с тонким app-таргетом и локальным SPM-пакетом. Вся логика живёт в
библиотеках и тестируется без запуска приложения; app-таргет только собирает их вместе
и держит системные API.

Приложение помечено `LSUIElement` — нет иконки в Dock, нет главного окна. Настройки
открываются отдельным обычным окном из контекстного меню чёлки.

### Модули

| Модуль | Ответственность | Зависимости |
|---|---|---|
| `NotchCore` | Машина состояний, геометрия чёлки, пороги курсора. Без UI и без AppKit | — |
| `MediaBridge` | Протокол `NowPlayingProvider`, реализации на адаптере и AppleScript, агрегатор, супервизор процесса | — |
| `NotchStore` | GRDB: схема, миграции, FTS5, контент-адресуемое хранилище блобов | — |
| `ClipboardKit` | Опрос пастборда, разбор типов, фильтры приватности, дедуп, вытеснение | `NotchStore` |
| `StashKit` | Заметки и закреплённые сниппеты | `NotchStore` |
| `NotchUI` | Вьюхи, дизайн-токены, morph-фигура, анимации | `NotchCore`, модели |
| `NotchApp` | Окно-панель, отслеживание курсора, глобальный хоткей, вставка через CGEvent, онбординг разрешений, сборка | всё выше |

Отслеживание курсора и хоткей изначально были отписаны `NotchCore`, но при реализации
переехали в app-таргет: оба привязаны к AppKit и Carbon и пробили бы дыру в главном
свойстве этого слоя — полной независимости от AppKit, которую финальное ревью проверило
механически и подтвердило. Логика порогов осталась в `NotchCore`, где и тестируется;
в app-таргете живёт только доставка событий.

Правило зависимостей: `NotchUI` не знает про `ClipboardKit` и `StashKit` напрямую — она
получает готовые модели представления. Это позволяет тестировать вьюхи на фикстурах.

### Внешние зависимости

- **GRDB.swift** — SQLite, миграции, FTS5
- **KeyboardShortcuts** — обёртка над Carbon `RegisterEventHotKey` плюс готовый UI переназначения
- **mediaremote-adapter** — вендорим в репозиторий, чтобы сборка не зависела от внешнего состояния
- **swift-snapshot-testing** — только в тестовых таргетах

## 4. Стратегия чтения музыки

### Проблема

До macOS 15.4 приватный фреймворк MediaRemote отдавал «сейчас играет» из любого
источника. В 15.4 Apple потребовала приватный entitlement, который невозможно получить
самоподписью, и все сторонние приложения этого класса перестали работать. На macOS 26.3
ограничение действует.

### Решение

`mediaremote-adapter` загружает MediaRemote не из нашего процесса, а через `/usr/bin/perl`:
этот бинарник подписан Apple и нужный entitlement у него есть. Адаптер работает
долгоживущим дочерним процессом и стримит построчный JSON на stdout.

Данные на выходе: заголовок, артист, альбом, обложка, длительность, позиция, признак
воспроизведения, bundle id источника. Команды (`play/pause`, `next`, `previous`, `seek`)
уходят тем же путём, поэтому YouTube в Chrome управляется так же, как Apple Music.

Позиция трека не опрашивается. Провайдер отдаёт точку отсчёта и темп, дальше UI
интерполирует локально — прогресс едет плавно без нагрузки.

### Слой источников

```
protocol NowPlayingProvider {
    var snapshots: AsyncStream<NowPlayingSnapshot?> { get }
    func send(_ command: MediaCommand) async throws
    var isAvailable: Bool { get }
}
```

Две реализации: `MediaRemoteAdapterProvider` (универсальная) и `AppleScriptProvider`
(Spotify и Music.app, где он точнее и надёжнее). Агрегатор выбирает активный источник и
обогащает данные адаптера данными AppleScript, когда играет один из этих двух плееров.

Протокол существует именно ради риска №1 из §11: если MediaRemote закроют полностью,
пишется третья реализация на браузерном расширении, и UI не меняется.

## 5. Окно

Самая капризная часть проекта — вся работа с AppKit сосредоточена здесь.

Панель это `NSPanel` со стилем `.nonactivatingPanel`, уровнем выше меню-бара,
`collectionBehavior = [.canJoinAllSpaces, .stationary, .fullScreenNone, .ignoresCycle]`,
прозрачным фоном и отключённой системной тенью (свечение рисуем сами).

**Размер окна постоянен** и равен максимальному развороту. Анимируется только содержимое
внутри: изменение фрейма `NSWindow` во время пружины даёт рывки.

**Клики по меню-бару.** Окно живёт с `ignoresMouseEvents = true`. Курсор отслеживается
глобальным монитором `mouseMoved` — он не требует разрешений. При входе курсора в горячую
зону события включаются, при выходе выключаются обратно.

**Фокус.** Неактивирующаяся панель не забирает фокус, поэтому целевое приложение остаётся
фронтовым и вставка работает. Исключение — раскрытая панель с полем поиска, где нужен ввод
с клавиатуры: там `canBecomeKey` временно истинно. При разворачивании запоминается
`NSWorkspace.shared.frontmostApplication`; перед вставкой фокус возвращается ему, и только
после этого посылается `⌘V`.

**Геометрия.** Высота чёлки берётся из `NSScreen.safeAreaInsets.top`, ширина вычисляется
как `frame.width - auxiliaryTopLeftArea.width - auxiliaryTopRightArea.width`. Никаких
захардкоженных значений под конкретную модель.

Протокола `NotchGeometryProvider` в реализации нет и не появилось: обе цели, ради которых
он задумывался, достигнуты дешевле. Тестируемость даёт инъекция значения `ScreenMetrics`
вместо `NSScreen` — расчёт проверяется на выдуманных конфигурациях экранов без единого
мока. Синтетическая чёлка для внешних мониторов вынесена за пределы первой версии (§13),
так что второй реализации протокола сейчас не существует и абстракция была бы пустой.
Расчёт живёт в `NotchGeometryCalculator`; мост от `NSScreen` — единственное место,
где AppKit превращается в данные.

Если внешние мониторы вернутся в работу, протокол вводится тогда — с реальным
вторым потребителем, а не заранее.

**Фуллскрин.** На дисплеях с чёлкой в полноэкранном режиме меню-бар скрыт, а область
выреза становится чёрной — панели там негде жить. В фуллскрине панель отключается,
доступным остаётся только глобальный хоткей.

## 6. Хранилище

Расположение: `~/Library/Application Support/kz.mobilefirst.notchka/`
— `notch.sqlite` и каталог `blobs/`.

Блобы контент-адресуемые: путь `blobs/<первые 2 символа хеша>/<хеш>`, что даёт дедуп
бесплатно — одинаковый скриншот, скопированный дважды, хранится один раз.

### Схема

```sql
clipboard_items(
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL,              -- text | image | file
  content_hash TEXT NOT NULL UNIQUE,
  text_body TEXT,                  -- тело для text; имя файла для file
  blob_path TEXT,                  -- для image и file
  byte_size INTEGER NOT NULL,
  source_bundle_id TEXT,
  source_app_name TEXT,
  created_at DATETIME NOT NULL,
  last_used_at DATETIME NOT NULL,
  is_pinned BOOLEAN NOT NULL DEFAULT 0
)

notes(id, body TEXT NOT NULL, created_at, updated_at)

snippets(id, label TEXT NOT NULL, value TEXT NOT NULL, icon TEXT,
         color_hex TEXT, sort_order INTEGER NOT NULL,
         is_sensitive BOOLEAN NOT NULL DEFAULT 0, created_at, updated_at)
```

Поиск: одна FTS5-таблица `search_index(owner_kind, owner_id, title, body)`, наполняемая
из кода при записи в любую из трёх таблиц. Один запрос обслуживает сквозной поиск.

## 7. Поведение модулей

### Музыка

Активный источник определяется агрегатором. Обложка кэшируется по хешу. Акцентный цвет
извлекается из обложки: берётся доминирующий насыщенный оттенок, яркость и насыщенность
зажимаются в диапазон, гарантирующий контраст к чёрному фону, переход анимируется 600 мс.

**Эквалайзер декоративный.** Реальный спектр чужого приложения недоступен без установки
виртуального аудиодрайвера. Визуализация реагирует на факт воспроизведения и темп, но не
на звук. Это осознанное ограничение, а не недоделка.

### Буфер обмена

`NSPasteboard.general.changeCount` опрашивается раз в 0.4 с на низкоприоритетной очереди —
публичного уведомления об изменении пастборда в macOS нет. Опрос приостанавливается, когда
`CGEventSource.secondsSinceLastEventType` превышает 60 секунд: неактивный пользователь
ничего не копирует.

Типы: строка, RTF (приводится к строке), PNG/TIFF, file-url.

Приватность в три слоя:
1. игнорируется тип `org.nspasteboard.ConcealedType` — его ставят менеджеры паролей;
2. игнорируются `org.nspasteboard.TransientType` и `org.nspasteboard.AutoGeneratedType`;
3. чёрный список приложений по bundle id фронтового приложения на момент копирования.
   По умолчанию: 1Password, Bitwarden, Keychain Access. Список редактируется в настройках.

Дедуп по SHA-256: повтор поднимает `last_used_at` существующей записи, а не создаёт дубль.

Лимиты: 500 записей, 30 дней, 2 ГБ блобов — срабатывает первый достигнутый. Закреплённые
элементы из ротации исключены. Значения настраиваемые.

### Заметки

Поле ввода сверху, `⌘↩` сохраняет. Клик по заметке разворачивает inline-редактор.
Простой текст без markdown-рендера: редактор размером с ладонь не место для форматирования.

### Пины

Метка, значение, иконка, цвет, порядок перетаскиванием. Значение можно пометить
чувствительным — тогда в панели оно маскируется точками, но вставляется целиком.

### Вставка

Клик вставляет: значение пишется в `NSPasteboard.general`, фокус возвращается запомненному
фронтовому приложению, затем `⌘V` посылается через `CGEvent` в `.cghidEventTap`.
`⌥`клик только копирует.

Оригинальное содержимое пастборда не восстанавливается. Это сознательно: восстановление
через задержку ломает приложения, читающие буфер асинхронно, и даёт непредсказуемые гонки.

### Поиск

Одно поле, FTS5, результаты сгруппированы по источнику. Открывается по `⌘F` или просто
началом набора текста при раскрытой панели. Навигация `↑`/`↓`, вставка `↩`.

## 8. Движение

Единственный источник истины — `NotchState { closed, peek, expanded(Tab) }`.

| Из | Событие | В |
|---|---|---|
| `closed` | Курсор в горячей зоне 120 мс | `peek` |
| `closed` | Хоткей | `expanded(последняя вкладка)` |
| `closed` | Сменился трек | `peek` на 2 с, затем обратно |
| `peek` | Клик | `expanded(музыка)` |
| `peek` | Хоткей | `expanded(последняя вкладка)` |
| `peek(.hover)` | Курсор вне зоны 250 мс | `closed` |
| `expanded` | `Esc`, клик вне панели, хоткей | `closed` |
| `expanded` | `⌘1`…`⌘4`, `⇥` | `expanded(другая вкладка)` |
| любое | Активное приложение ушло в фуллскрин | `closed`, панель отключена |

В `expanded` курсор панель не закрывает: уводить мышь во время работы с лентой буфера —
нормально, закрытие только явное.

Уход курсора закрывает лишь `peek(.hover)`, а не `peek` вообще: автопик по смене трека
возникает, когда курсор далеко от чёлки, и закрывается собственным таймером. Единого
события «курсор вышел» без предшествующего «вошёл» не бывает — это гарантирует
`HoverDebouncer`, и на этом инварианте держится корректность строки выше.

**Что удерживает уже открытую панель.** Горячая зона — это прямоугольник входа, и она
намеренно мала: вырез плюс несколько пунктов. Раскрытая панель заметно больше, поэтому
проверять по ней принадлежность курсора нельзя — подводя мышь к видимой панели,
пользователь вышел бы из зоны входа и панель закрылась бы под курсором.

Правило: пока панель открыта, попадание курсора проверяется по **текущим видимым
границам самой панели**, а не по исходной зоне выреза. Ведёт себя как обычное меню.
Реализуется в плане 2, вместе с настоящими размерами панели — привязывать логику
к временным числам отладочной вьюхи бессмысленно.

Форма панели это одна кастомная SwiftUI `Shape` с анимируемыми шириной, высотой и радиусами
и **вогнутыми верхними углами** — именно они создают ощущение, что панель вылита заодно
с корпусом, а не наложена поверх. Фигура живёт внутри окна постоянного размера (§5):
анимируется она, а не `NSWindow`.

| Переход | Параметры |
|---|---|
| Открытие peek и разворот | `.spring(response: 0.34, dampingFraction: 0.68)` |
| Закрытие | `.snappy(duration: 0.26)` |
| Появление содержимого | stagger 30 мс на строку, `blur 8 → 0`, `translateY 7 → 0` |
| Смена акцентного цвета | 600 мс |

Пороги курсора: вход в горячую зону должен продержаться 120 мс, выход — 250 мс. Это
убирает дребезг, когда курсор просто проезжает мимо чёлки к меню-бару. Горячая зона —
прямоугольник чёлки, расширенный на 6 pt по горизонтали и 4 pt вниз.

Живые реакции:
- смена трека — панель сама выныривает в peek на 2 секунды, обложка въезжает сбоку;
- копирование — импульс по контуру чёлки цветом типа элемента, без разворачивания;
- вставка пина — чип уезжает вниз к курсору и гаснет;
- обложка использует общую геометрию между peek и разворотом: растёт как единый объект.

Дисциплина: анимируются только `transform`, `opacity`, `clip-path` и параметры фигуры.
При включённом системном Reduce Motion морф заменяется кросс-фейдом, живые реакции
глушатся. В состоянии `closed` таймеры и рендер спят — в простое приложение не работает.

## 9. Управление с клавиатуры

| Сочетание | Действие |
|---|---|
| `⌥Space` | Развернуть или свернуть панель (переназначается) |
| `⌘1`…`⌘4` | Вкладки: музыка, буфер, заметки, пины |
| `⇥` | Следующая вкладка |
| `⌘F` | Поиск |
| `←` `→` `↑` `↓` | Навигация внутри вкладки |
| `↩` | Вставить выбранное |
| `⌥↩` | Скопировать без вставки |
| `Esc` | Свернуть |

Глобальный хоткей регистрируется через Carbon `RegisterEventHotKey` — разрешений не требует.

## 10. Разрешения и ошибки

Требуется ровно одно разрешение — **Accessibility**, и только для посылки `⌘V`.
Отслеживание мыши и глобальный хоткей работают без разрешений.

Онбординг: при первом запуске панель показывает шаг с кнопкой, ведущей прямо в нужный
раздел System Settings, и подхватывает выдачу разрешения без перезапуска приложения.

| Отказ | Поведение |
|---|---|
| Адаптер упал | Супервизор поднимает с паузой 1→2→4→…→30 с; UI переключается на AppleScript |
| Оба источника молчат | Вкладка честно показывает «источник недоступен», а не замороженный последний трек |
| Нет Accessibility | Клик копирует вместо вставки и объясняет причину со ссылкой на настройки |
| База повреждена | Миграции GRDB, суточная копия файла базы, восстановление из копии |
| Блоб потерян | Запись помечается битой и исчезает из ленты при следующей чистке |

Ошибки не глотаются: каждая ветка отказа либо восстанавливается, либо становится видимой
в UI.

## 11. Риски

**1. Адаптер может не завестись, или Apple закроет и этот путь.**
Первым шагом плана идёт спайк: доказать чтение трека из YouTube в Chrome. До того, как
написана хоть одна вьюха. Если путь мёртв — пишется провайдер на браузерном расширении
с native messaging, остальная архитектура не меняется благодаря протоколу из §4.

**2. Окно над меню-баром.**
Вторым шагом идёт голая панель без содержимого, на которой проверяется: не крадёт фокус,
не блокирует клики по меню-бару, живёт на всех Spaces, корректно исчезает в фуллскрине.
Ловить это на пустом месте дешевле, чем в готовом приложении.

**3. Расход батареи от опроса буфера.**
Смягчается низкоприоритетной очередью и паузой при неактивности пользователя. Проверяется
замером в Instruments до того, как приложение станет ежедневным.

**4. Приватные данные в базе.**
База не шифрована и лежит в Application Support. Защита — три слоя фильтров и флаг
чувствительности у пинов. Осознанный компромисс для личной машины: шифрование потребовало
бы ввода пароля при каждом запуске, что убивает смысл инструмента.

## 12. Тестирование

Swift Testing, не XCTest. Логика вынесена в библиотеки, поэтому тесты не поднимают
приложение и идут быстро.

| Область | Что проверяется |
|---|---|
| `NotchCore` | Все переходы машины состояний; дребезг курсора (проезд мимо за 100 мс не должен открывать панель); геометрия на моках экранов |
| `MediaBridge` | Парсинг JSON на фикстурах: обрывы строк, мусор, трек без обложки, смена источника; супервизор и backoff на виртуальных часах; выбор активного источника |
| `ClipboardKit` | Каждый слой фильтров приватности; дедуп; вытеснение по всем трём лимитам |
| `NotchStore` | Миграции с непустой базой; ранжирование FTS; дедуп блобов; восстановление после потери блоба |
| `StashKit` | CRUD, порядок после перетаскивания, маскировка чувствительных значений |
| Цвет из обложки | Golden-тесты на наборе обложек: проверяется контраст к чёрному, а не точный RGB |
| `NotchUI` | Снапшоты четырёх вкладок в трёх состояниях |

Цель 80% относится к библиотекам, где она осмысленна. App-таргет — тонкий слой над
системными API (окно, CGEvent, разрешения), он покрывается ручным чек-листом: реальная
вставка в стороннее приложение, поведение над фуллскрином, второй монитор, поведение
после сна и пробуждения, поведение при смене трека в свёрнутом состоянии.

## 13. Вне первой версии

Осознанно отложено, чтобы чёлка не превратилась в помойку:

- внешние мониторы без чёлки (геометрия уже абстрагирована — добавляется провайдером);
- перетаскивание файлов в чёлку как в полку AirDrop;
- markdown, теги и синхронизация заметок;
- настоящий аудиоспектр — требует установки виртуального аудиодрайвера;
- виджеты, погода, календарь, таймеры;
- шифрование базы.

## 14. Критерии готовности

Первая версия считается готовой, когда на реальной машине выполняется всё перечисленное:

1. Трек из YouTube в Chrome виден в панели, пауза и переключение работают.
2. Наведение на чёлку открывает peek за 120 мс, проезд курсором мимо её не открывает.
3. Клики по меню-бару проходят насквозь, когда панель свёрнута.
4. Скопированный текст, скриншот и файл появляются в ленте буфера с указанием источника.
5. Копирование из менеджера паролей в ленту не попадает.
6. Клик по пину вставляет значение в активное приложение, `⌥`клик только копирует.
7. Поиск находит запись из буфера, заметку и пин одним запросом.
8. Перезапуск адаптера не роняет приложение и не оставляет замороженный трек.
9. В свёрнутом состоянии приложение не потребляет заметного CPU.
10. Reduce Motion выключает морф.
